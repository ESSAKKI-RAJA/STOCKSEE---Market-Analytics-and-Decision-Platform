# 05 - DATA MODEL MAP

## 1. Overview
The STOCKSEE backend utilizes SQLAlchemy ORM with an intended PostgreSQL database (via Supabase) and SQLite for local development.

## 2. The Alembic Divergence
A comprehensive database audit uncovered a major discrepancy between the codebase and the actual database schema generated via Alembic migrations.

### What is Defined in Code (`app/models/`):
- `user.py`: `User`, `UserPreference`
- `stock.py`: `CompanyProfile`, `MarketDataCache` (SQLAlchemy 2.0 style), `OHLCVCache`, `TechnicalIndicator`, `NewsArticle`, `SentimentScore`
- `intelligence.py`: `AIReport`, `SourceLog`
- `cache_models.py`: `MarketDataCache` (SQLAlchemy 1.4 style), `NewsArticle`, `SentimentScore`, `AIReport`, `SourceLog`, `ApiHealthLog`, `UserWatchlist`

### What is Actually in the Database (`alembic/versions/d75fd313a675_init.py`):
- `ai_reports`
- `api_health_logs`
- `market_data_cache`
- `news_articles`
- `sentiment_scores`
- `source_logs`
- `user_watchlists`

### Root Cause
The `app/models/__init__.py` file only exports the models from `cache_models.py`. Therefore, when Alembic autogenerated the initial migration, it ignored all user and stock entities.

### Consequence
The `User`, `Portfolio`, and `CompanyProfile` tables **do not exist** in the deployed production database. Any attempt to query them will result in an immediate `ProgrammingError` (relation does not exist).

## 3. Data Model Risk Analysis
- **Orphan-Risk**: Because `users` does not exist, `user_watchlists` does not have a strict Foreign Key constraint enforced against a parent table. The `user_id` is just a string column.
- **Inconsistent Naming**: Some models use standard integer primary keys, while `cache_models.py` uses string UUIDs. Some use SQLAlchemy 2.0 `Mapped[]` typing, while others use SQLAlchemy 1.4 `Column()` syntax.

## 4. Remediation Plan (Future Bin)
Do **not** manually alter the database in this Bin. The remediation plan for Bin 3 is:
1. Standardize all models to SQLAlchemy 2.0 syntax.
2. Ensure `app/models/__init__.py` correctly imports all required classes.
3. Generate a new Alembic migration (`alembic revision --autogenerate -m "Add core entities"`).
4. Apply the migration locally, test thoroughly, then deploy.
